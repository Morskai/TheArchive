# 演员 actor.info 格式（版本 1）

演员资料在演员库“新增演员 → 扫描添加／导出资料”中管理。文件名为 actor.info，内容为 UTF-8 JSON，格式版本1，每份最多1MiB。开发与兼容边界见[开发指南](DEVELOPMENT.md)，操作见[使用指南](USAGE.md)。

设置中的作品资料导入与导出已经移除，不再读取或生成 film.info.json。影片资料在软件内编辑，完整恢复使用软件备份。影片主动扫描和正常启动不读取演员info、不创建演员；当前产品没有目录监控。

## 演员actor.info字段

文件名固定actor.info（扩展名.info），内容仍JSON。扫描不读取actor.info.json。`format_version: 1`、`kind: "actor"`为必需格式标记；未知字段及作品文档拒绝。`name`必需且非空，长度与软件姓名规则相同。别名为字符串数组；数组成员内的顿号、中文逗号或英文逗号统一拆成多个别名（与手动输入一致），先拒绝控制字符，再去首尾空白、大小写不敏感去重并去掉与姓名相同的冗余别名。

| 字段 | 扫描用途 |
| --- | --- |
| `name` | 必需，姓名；参与当前库姓名／别名候选匹配，确认更新后写入 |
| `aliases` | 可选数组；缺省保留，null／空数组清空；参与交叉匹配，别名排序不影响完全重复判断 |
| `birth_month` | 出生信息，字符串YYYY或YYYY-MM；年份1900至本年，年月1900-01至本月；缺省保留，null／空文本清空 |
| `height_cm` | 身高整数100–230；缺省保留，null清空 |
| `cup` | 单个英文字母；缺省保留，null／空文本清空 |
| `bust_cm`／`waist_cm`／`hip_cm` | 三围整数40–160；缺省保留，null清空 |
| `id` | 导出内部演员ID留底，导入忽略，不参与识别／不改变软件身份 |
| `photo` | 导出照片说明，导入忽略路径；照片只取同目录actor主名支持格式图片 |
| `film_ids` | 导出当前人工出演影片内部ID留底，导入忽略，不修改绑定关系 |
| `filmography` | 可选出演清单数组；每项 `folder_name`＋`video_files`，确认后只补精确匹配的缺少关系；缺省／空数组不删除已有关系 |

```json
{
  "format_version": 1,
  "kind": "actor",
  "id": "actor-example",
  "name": "示例演员",
  "aliases": ["示例别名"],
  "birth_month": "1990-05",
  "height_cm": 165,
  "cup": "D",
  "bust_cm": 86,
  "waist_cm": 60,
  "hip_cm": 88,
  "photo": "actor.jpg",
  "film_ids": ["film-example"],
  "filmography": [
    {
      "folder_name": "示例影片文件夹",
      "video_files": ["episode1.mp4", "episode2.mkv"]
    }
  ]
}
```

## 扫描与确认

出生信息只知道年份时可写 `"birth_month": "2003"`；知道月份时可写 `"birth_month": "2003-05"`。手动编辑、扫描、导出和备份恢复均保留提供的精度，详情原样显示2003或2003-05，不自动补月份。仍拒绝未来年份／年月、错误月份、全角数字及其它日期格式；字段名和格式版本保持，旧年月资料继续使用。

可选择一个演员文件夹或包含多位演员的资料文件夹，所选根及子目录都参与递归；每个目录必须有有效actor.info才识别，目录名任意，不要求视频。照片可选，只有照片没有info不识别。同目录actor主名图片按JPG > JPEG > PNG > WebP > AVIF优先、大小写不敏感、坏图回退；多个图片仍为一位演员，不借父子照片。有图片候选但全部不可读，该目录整条失败；无照片的有效info可新增。

只按当前姓名／别名完整交叉找候选，不用历史目录／外部ID／照片相似度。主姓名＋完整无序别名集合规范化后唯一完全一致时默认更新该演员；无候选列待新增。只有姓名／别名交叉但完整身份不同的资料需明确更新信息、新增演员或跳过；历史库存在多个完全一致身份时仍须选择，不能任意选一个。姓名＋无序别名集合规范化后完全重复不能新增（包括手动创建／编辑）；同批多目录对应同一演员或相同新身份需选一份，其余跳过，不顺序覆盖。

更新保留软件内部演员ID，写name及提供的aliases／个人字段；缺省保留、明确空值清空。有效照片校验后保存所选原图路径及原图字节SHA-256；路径和指纹都相同才跳过，变化直接替换，无照片不删除旧路径，不保存永久照片BLOB。新建生成内部ID，缺省个人资料留空。film_ids、id和photo仅为档案说明，导入忽略；收藏、演员标签、历史和设置不通过actor.info修改。确认绑定源文件／候选、演员资料、出演关系及影片扫描清单，过期拒绝；有实际写入先保护，个人资料、照片路径和出演追加共用整批事务，失败回滚。个人资料没有变化仍可补出演，无任何变化才跳过。

### 出演清单的校验与精确匹配

`filmography` 缺省表示旧文件只处理个人资料；提供时必须是数组（允许 `[]`，不接受null）。每项只允许 `folder_name` 与 `video_files` 两个必需键。文件夹名及视频文件名是1–255字符的非空字符串，不能是 `.`／`..`，不能含控制字符、路径分隔符或冒号；不去首尾空白、不改变大小写。`video_files` 必须是非空字符串数组，不允许重复文件名；相同文件夹＋无序文件清单重复条目只计一次。整个文件仍受1MiB限制，未知键、错误类型及非法清单使该演员目录失败。

匹配只看已收录、来源启用且未移除的当前影片卡片：文件夹名与直属视频完整文件名（含扩展名）全部完全一致；清单顺序无关。视频范围复用成功影片扫描结果，每目录分别比较，不合并父子目录。盘符／上层分类目录／内部ID／片名／编号不参与，不增加模糊候选或备用匹配。

完成演员身份及同批资料选择后，最终预览只显示出演关系三个数量：**可关联**为唯一匹配且尚未关联；**已有**为唯一匹配且已关联；**未找到**为没有唯一匹配。本次明确跳过的演员目录不计，单位为演员与影片关系（同一影片关联两位演员计两条）；同一演员的多条描述落到同一卡片只计一条。未找到可展开文件夹名、完整视频清单和原因；多个卡片满足时统一为未找到，原因“找到多个相同条目，未关联”。不单列歧义统计。

用户最终确认才补可关联关系，已有／未找到跳过，结果保留未找到明细；保留其它人工出演。清单未写某影片、空数组或旧文件缺字段都不删除已有关系。导入不创建影片、添加来源或触发扫描；演员仍按姓名／别名确认，文件内部ID不认人。

## 演员导出、照片与备份

“导出资料”选演员／父目录后直接点击“确认导出”，写其“ActorExports”子目录；界面不再有预览步骤，确认时后台仍生成／复验位置和归属凭据。旧中文总目录保留，不迁移或删除；可选软件资料目录之外的位置，清除重装前应将副本放在外部。当前姓名（别名）只作导出目录名，无别名省括号；info真实姓名／别名不因非法字符／过长／同名消歧而改。文件为actor.info JSON（个人资料、照片说明、出演清单），保存了照片路径且原图可读时主动生成actor.jpg；无路径仅info仍满足扫描条件，图片不嵌入JSON。已有照片路径不可读时明确报导出照片不可用，不用显示缓存冒充原图，不发布不完整副本；先重新选择可用照片或明确移除照片，再导出。

出演清单由已有关系和最新成功影片扫描中的完整目录清单生成，不读取或修改媒体原件；停用来源的已有当前清单仍可导出。历史位置／历史视频名不能拼成当前清单。所选演员有关系缺少可靠目录清单时，导出明确提示连接片库并完成扫描，拒绝不完整导出，旧副本不改；演员未被选择不会因此阻止其它演员导出。超出1MiB同样拒绝，不生成无法再次导入的文件。

.thearchive-actor.json拥有权校验继续保护覆盖与改名旧目录清理；外部修改／未知文件／链接拒绝，只读旧文件发布前拒绝。待覆盖或清理的目录若包含任何已保存演员的照片来源，整批在发布前拒绝并提示另选导出位置，不删除／重编码该来源，也不自动改写照片路径；导出后再扫描导回及其它演员共用照片同样受保护。旧拥有的actor.info.json副本可通过拥有权校验在再次导出时替换为actor.info，绝不作为扫描输入。发布后清理失败保留拥有权并报告已发布数。

导出副本不自动同步，软件编辑后再次导出才刷新，不回写原目录。演员资料和出演关系可通过actor.info在重新扫描影片后恢复；演员标签不在此格式中，完整软件数据恢复仍使用软件备份。软件备份包含照片路径／指纹、姓名／别名／个人信息／时间／内部ID／收藏／出演、独立演员标签及历史兼容资料，不含原图或派生缓存。头像缓存绑定演员ID及已记录的路径／指纹，恢复旧备份不能复用后来换照的缓存。显示可使用有效缓存，缓存清空后原图不可读则占位；会话停止与重试范围见[图片规则](USAGE.md#备份恢复与图片缓存)。

schema18→19受保护移除actor_photos旧JPEG，按用户明确决定直接丢弃，不自动导出另存；没有可靠原路径不生成actor_image_sources记录，不从历史目录、姓名或影片猜路径。原演员身份、个人资料、收藏与出演保留；旧备份恢复执行同一迁移。schema17→18移除actor_import_sources历史目录表的既有边界保持。主动备份、迁移保护及恢复前保护继续遵守资料保护规则，不能因移除永久照片推断为无需保护。

## 兼容与回退

当前数据库 schema 23。旧程序不能直接读取新版数据库；回退源码与恢复升级前资料是两个步骤，不得删除数据库或通过卸载重置代替迁移。照片路径化与演员独立管理的历史迁移仍由源码执行保护与事务，公开仓库首个提交不代表重建用户资料。
